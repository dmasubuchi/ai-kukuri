# Architecture

Note: the CLI messages and the page headings generated by the tools are currently Japanese. Localisation is on the roadmap ([roadmap](roadmap.md)).

## Overview

```
workspace/ (Git tracks only rules, registry, skills and bin)
├── AGENTS.md  CLAUDE.md         Entry point for each AI product. Makes it read rules/common.md etc.
├── rules/common.md              Source of truth for product-independent common conventions
├── registry/projects.json       Project ledger (name, aliases, directory)
├── skills/                      Common procedures (Markdown)
├── bin/                         This kit's commands (Python standard library only)
├── knowledge/
│   ├── journal/YYYY-MM-DD.md    Journal: what happened (append-only)
│   ├── pages/                   Living Wiki: what is known now
│   ├── records/<sha256>.txt     Copies of original text (preserved by hash)
│   └── imports/                 Per-version catalog of imports
├── tasks/
│   ├── baseline.json            Fixed baseline of the TODOs
│   └── events.jsonl             Append-only change history
├── projects/  input/  output/   Project repos, inputs, deliverables (outside the workspace Git)
└── runtime/                     Machine- and product-specific settings, credentials, history (outside Git)

(The generated .gitignore also excludes knowledge/ tasks/ runtime/. Git tracks only the conventions, ledger, skills and commands.)
```

## Data flow

```
 Event ──kukuri-journal add──▶ Journal (append-only, with sources)
                                   │  update: wiki:<slug>#<key> = <what is known now>
                                   ▼
                     kukuri-wiki plan (writes nothing)
                                   │  a person or the AI reviews the content
                                   ▼
                     kukuri-wiki apply --write ──▶ Living Wiki (pages/)
                                   │ keeps history, conflicts and unconfirmed items with sources and dates
 Journal records ──kukuri-journal evidence──▶ kukuri-tasks add/update (with evidence)
```

## Wiki update rules (`kukuri-wiki`)

The Living Wiki is **reconstructed** from the Journal. All records addressed to a page are re-judged from the beginning in **order of record timestamp**, not in order of appending, so the result depends neither on the order of appends nor on how many times or when `apply` is run (verified with all permutations and with runs that interleave `apply`).

| Situation (judged in timestamp order) | Behavior |
|---|---|
| A new fact is a `decision`/`result` | Added to `## 現在わかっていること` ("What is known now") |
| A new fact is a `proposal`/`observation`/`request` | Added to `## 未確認・矛盾` ("Unconfirmed / conflicting"); not treated as settled |
| A newer decision/result reconfirms content that is already settled | Timestamp and source are updated |
| A proposal/observation restates already-settled content | The settled source and date are not replaced |
| A later `decision`/`result` with different content | The old statement is moved to history (with source and date) and replaced by the new one |
| A later record of the same kind on the same day | Treated as an update (the old statement goes to history) |
| Different results after a decision on the same day | Conflict. Both are kept in "Unconfirmed / conflicting" with source and date |
| A proposal/observation differing from settled content | Kept as a conflict (not settled) |
| A newer decision/result for an unconfirmed item or conflict | Resolved. The old candidates remain in history |

Safety stops:

| Situation | Behavior |
|---|---|
| Existing free-form page (no markers) | Not updated automatically (`manual_legacy_page`) |
| Old-format page without the `## 反映済みの記録` ("Applied records") section | Stops without updating (`migration_required`). Review the content, then run `kukuri-wiki migrate <slug> --write` to reconstruct from the Journal and attach the ledger. The old version's history is kept under `## 移行の記録` ("Migration record") |
| Page holding claims whose sources are not in the Journal (hand-edited) | Stops without updating (`manual_review`) |
| Previously applied records are no longer all present in the current Journal (records missing or deleted) | Stops without updating (`missing_source`), so that reconstruction does not lose history or sources. Restore the Journal or have a person review it |
| `apply` run concurrently | Reading, judging and writing happen inside the same lock, so no update is lost |

`--date` and `--entry` of `plan`/`apply` only narrow which records are shown in the result. Judgment and writing use all records addressed to that page.

Other page section headings the tool writes are `## 履歴` ("History") and the sections named above.

## Record layers (`kukuri-memory`)

Original text (`records/`, preserved by hash) / organized pages (`pages/`) / search index (SQLite, regenerable). Search returns organized pages and recent journal entries first, then the stored original text. If an import source is missing, it stops without replacing the current index.

## Design decisions

- No resident process, external service or database server. State is files plus an append-only history.
- Product-specific settings are isolated under `runtime/<product>/` (`kukuri-launch.py`). They are not mixed into the common conventions.
- When the basis of a change (original line, quotation, hash) cannot be verified, the update is refused.
